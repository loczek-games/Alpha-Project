# Roblox Studio Setup

Two ways to get the project into Studio. **Option A (Rojo)** takes about two
minutes and is recommended. **Option B** is plain copy-and-paste and needs no
extra tools.

The map (Dead Mall with 8 zones, Lobby and Dark Room), all UI and all
RemoteEvents are generated by code. You only need the scripts.

---

## Option A: Rojo (recommended)

1. Install Rojo 7.4+ (`aftman add rojo-rbx/rojo` or download it from
   https://github.com/rojo-rbx/rojo/releases) and install the **Rojo plugin**
   in Studio.
2. Open a **new Baseplate** place in Studio.
3. In a terminal, from the repository root:
   ```bash
   rojo serve default.project.json
   ```
4. In Studio, open the Rojo plugin and click **Connect**. Every script,
   folder and ScreenGui from `docs/EXPLORER_HIERARCHY.md` appears in the Explorer.
5. Continue with **Studio settings** below.

To produce a place file without Studio running:
`rojo build default.project.json -o CaughtOnCamera.rbxlx`

---

## Option B: Manual copy-paste

1. Open a **new Baseplate** place in Studio.
2. Create the folders:
   - `ReplicatedStorage` → Folder **Config**, Folder **Modules**, Folder **Remotes** (leave Remotes empty)
   - `ServerScriptService` → Folder **Services**, Folder **Anomalies** → inside it Folder **Behaviors**
   - `StarterPlayer/StarterPlayerScripts` → Folder **Controllers**
   - `Workspace` → Folder **Map** → inside it Folder **DeadMall**; Folder **AnomalySpawns**; Folder **Lobby**
3. For **every row in [`docs/SCRIPTS.md`](SCRIPTS.md)**, insert the listed
   class (Script / LocalScript / ModuleScript) at the listed location, rename
   it to exactly the listed name, delete the default code and paste the whole
   source file.
   - `Main.server.lua` → **Script** named `Main`
   - `ClientMain.client.lua` → **LocalScript** named `ClientMain`
   - every other `.lua` file → **ModuleScript** named after the file (without `.lua`)
4. Optional: in `StarterGui` create ScreenGuis named `HUD`, `AlbumUI`,
   `ResultsUI`, `ShopUI`, `DarkRoomUI`, `OverlayUI` with **ResetOnSpawn = false** (OverlayUI also ScreenInsets = None).
   If you skip this, the controllers create them automatically.

## Studio settings

1. **Home → Game Settings → Security → Enable Studio Access to API Services** = ON
   (lets DataStores save in Studio. Without it the game still runs with a temporary,
   non-saving profile and prints a warning).
2. The place must be **published** (File → Publish to Roblox) for DataStores,
   Game Passes and Developer Products to work.
3. **Game Settings → Avatar**: R15 is recommended (R6 also works).
4. Leave **Workspace.StreamingEnabled** as it is. The code handles streaming
   (teleports wait for the destination to load, zones and the Dark Room stream
   persistently).
5. Press **Play**. You spawn in the Lobby; after the countdown (10 s in Studio,
   25 s live) you are teleported into the Dead Mall and anomalies start appearing
   within a few seconds.

The auto-builder removes the template **Baseplate** part and stray
**SpawnLocations** (they would overlap the mall). Turn this off with
`GameConfig.Map.RemoveBaseplate` / `RemoveStraySpawns`.

## Monetization setup

1. Creator Dashboard → your experience → **Monetization**:
   - Create 4 **Passes**: Fast Camera, Extra Album Storage, Bigger Dark Room, VIP Photographer.
   - Create 4 **Developer Products**: Paranormal Surge, Blackout Event, Small Evidence Pack, Medium Evidence Pack.
2. Paste each ID into `ReplicatedStorage/Config/MonetizationConfig` (`Id = 0` → your id).
   An ID of `0` shows the item as *Unavailable* and nothing is ever prompted or granted for it.
3. Optional: create badges and paste their IDs into `GameConfig.Badges`
   (`PhotographedBack`, `ImpossibleFound`, `FirstPhoto`).
4. To test game pass perks in Studio without buying, set
   `GameConfig.Debug.StudioGrantAllPasses = true` (this only ever applies in Studio).

Developer Products are only granted inside `MarketplaceService.ProcessReceipt`
on the server. Each `PurchaseId` is stored in the buyer's save and saved before
`PurchaseGranted` is returned, so a receipt can never be granted twice.

## Admin / test commands

Type these in chat. They work for everyone during Studio play tests, for the
game creator, and for user IDs listed in `GameConfig.Admin.UserIds`. The
server checks permission for every command.

| Command | Effect |
|---|---|
| `/round start` | Skip the lobby countdown |
| `/round end` | End the current round (shows results) |
| `/spawn <AnomalyId>` | Force-spawn an anomaly, e.g. `/spawn TheObserver`, `/spawn FakePlayer` |
| `/event surge` / `blackout` / `falsealarm` / `rare` | Start a server event |
| `/evidence 50000` | Give yourself Evidence |
| `/anomalies` | Print every anomaly id to the Output window |
| `/resetdata` | Wipe your own save and kick (Studio only) |

## Sounds

`GameConfig.Sounds` uses built-in `rbxasset://sounds/...` files, which work in
every place with no uploads. Replace any `Id` with your own
`rbxassetid://` audio for a more polished shutter/ambience, or set it to `""`
to disable that sound. Set `Ambience.Id` to a looping mall-muzak track to
enable background ambience.

## Using your own map

MapService only builds when `Workspace.Map.DeadMall` and `Workspace.Lobby`
are empty. To hand-build or tweak the mall:

1. Press Play, select `Workspace.Map`, `Workspace.AnomalySpawns` and
   `Workspace.Lobby`, copy them, stop the game and paste them into Workspace
   (replacing the empty folders). You now own a fully editable copy.
2. Keep the conventions the code looks for:
   - light panels tagged `MallLight` with a `Zone` attribute and a child PointLight
   - fixtures tagged `MallClock`, `MallPainting`, `MallMirror`, `ExitSign`, `ArcadeCabinet`
     (see the header of `MapService` for the parts each one needs)
   - spawn marker parts in `Workspace.AnomalySpawns` with `Kind`
     (`Floor`, `Ceiling`, `DoorSlot`, `Dark`, `RunLane`, `Skylight`) and `Zone` attributes
   - zone bounds parts in `DeadMall.Zones` named after the zone id
   - `DeadMall.PlayerSpawns`, `DeadMall.NPCWaypoints` (attribute `Lane` = `West`/`East`)
   - Lobby parts tagged `DarkRoomEntrance` / `DarkRoomExit` (with a ProximityPrompt),
     `DarkRoomFrame` (attribute `Index`) and `DarkRoomNameplate`

## Adding a new anomaly (about 5 minutes)

1. Add an entry to `AnomalyConfig.List` with an `Id`, `Rarity`, `Weight`,
   `Behavior`, `Lifetime`, `PhotoDistance`, `Spawn`, `Icon` and `Description`.
2. Duplicate a similar module in `ServerScriptService/Anomalies/Behaviors`,
   rename it to your `Behavior` name, and change `Spawn` so it builds your
   anomaly and sets `record.Target` (the part to photograph).
3. Done. It is picked up automatically by the spawner, the photo system, the
   album, the Dark Room and the odds display.

## Adding a camera ability (NightCam / ThermalCam / GlitchCam)

1. In `CameraConfig`, set the camera's `Implemented = true` (it becomes purchasable).
2. Give anomalies that need it `RequiredAbility = "Night"` (or `Thermal` / `Glitch`)
   in `AnomalyConfig`. They only spawn while someone in the round has a camera
   with that ability equipped, and only players using such a camera can
   photograph them (others get "Your camera can't capture this one").
